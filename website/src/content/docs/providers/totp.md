---
title: TOTP (Authenticator Apps)
description: Learn how to implement Time-based One-Time Passwords (TOTP) in Authkestra.
---

Time-based One-Time Passwords (TOTP) allow users to authenticate using 6-digit codes generated by apps like Google Authenticator, Authy, or 1Password.

## Enabling TOTP

To use TOTP, enable the `totp` feature in your `Cargo.toml`:

```toml
[dependencies]
authkestra-engine = { version = "0.2.0", features = ["totp"] }
```

## Configuration

Authkestra's typestate builder pattern requires you to initialize the engine with TOTP support:

```rust
use authkestra_engine::Authkestra;

let engine = Authkestra::builder()
    .with_store(my_store)
    .with_totp() // Enables TOTP support
    .build()
    .unwrap();
```

## Registering a Device

To enroll a user, call `register_totp`. It generates a new base32 secret and an `otpauth://` provisioning URI. 

```rust
let (secret_b32, uri) = engine.register_totp(
    "user_123", // user ID
    "Authkestra", // Issuer (shows in app)
    "alice@example.com" // Account name
).await?;
```
You can convert the `uri` into a QR code using a frontend library (like `qrcode.js`) for the user to scan. The secret is automatically saved in the configured `CredentialStore`.

## Authenticating

To authenticate, simply accept the 6-digit code from the user and pass it to `authenticate`:

```rust
use authkestra_engine::auth::AuthInput;

let identity = engine.authenticate(AuthInput::Totp {
    user_id: "user_123".to_string(),
    code: "123456".to_string(),
}).await?;
```

### Built-in Replay Protection

Authkestra strictly adheres to [RFC 6238](https://datatracker.ietf.org/doc/html/rfc6238). It automatically tracks the highest `last_used_step` in the credential store, preventing the exact same code from being submitted more than once within the validity window. This completely mitigates replay attacks!
